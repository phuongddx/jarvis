Why it is built this way

Three properties hold regardless of what the indexer is doing. They are the reason a reindex cannot corrupt a query in flight.

The runtime never writes

Queries open a published index-<sha>.db read-only, with mode=ro&immutable=1. Index files are never mutated in place, so there is no lock contention and no torn read.

Publishing is atomic

A reindex writes a new versioned database, populates the package graph, and runs zoekt-git-index. Only once all of that succeeds does os.replace flip a small pointer file. A query already reading the old file keeps working, and a failure anywhere leaves the previous index live.

The package graph is rebuilt, not accumulated

Each reindex clears that repo's own outgoing dependency edges before recomputing them, so a dependency you removed stops showing up. The graph reflects each repo's last index run rather than every run it has ever had.

How it works

Seven layers, with storage in the middle. The runtime half only reads down into it; the indexing half only writes up into it. The two halves share no other contract.

Indexing reads git, not the filesystem

Language is detected by extension plurality across git ls-files, not a filesystem walk, because a walk also counts gitignored scratch directories that can outnumber a repo's own code. Optional source-build semantic work is the one stage allowed to fail without blocking the publish.

Exact and lexical query paths

The structural path returns exact ranges. The lexical path searches Zoekt directly. Nothing classifies your query or silently falls back: the agent picks the tool, which means you can predict which one ran.

Ten flat tools over stdio JSON-RPC

Every tool reports failure the same way, as an {"error": "..."} payload rather than a transport error, so a query bug never takes the server down mid-session.

Ten MCP tools

Every navigation tool takes repo, the slug from jarvis index, plus a symbol or path. Nine are operational; semantic search reports that the Homebrew distribution excludes it.

Navigation

Backed by SCIP. Exact ranges, not text matches.

  • goToDefinition resolve a symbol to its defining range
  • findReferences every occurrence across the indexed repo
  • callHierarchy incoming and outgoing calls
  • documentSymbols outline of one file
  • typeHierarchy supertypes and subtypes from bundled SCIP data

Search

Precise lexical search; the semantic tool is explicit about its Homebrew exclusion.

  • searchCode Zoekt trigram search, regex capable
  • semanticSearch HOMEBREW EXCLUDED

Cross-repo

Needs the dependency indexed too, or the edge cannot resolve.

  • blastRadius which other indexed repos depend on a package, up to two hops

Freshness

Index state and launches are explicit.

  • getIndexStatus published commit, and staleness against a working tree
  • indexRepo launch a detached index run for a git repo

What it does not do

Read this before installing. jarvis is deliberately narrow, and the gaps below are real rather than roadmap items.

Navigation and search

Four language families get the full SCIP tool set, including go-to-definition and find-references.

TypeScript TSX Python Java Kotlin Swift

Search only

With --search-only, ten more languages are searchable but have no navigation at all.

Go Ruby Rust C C++ C# PHP Scala Shell SQL
macOS and Linux only. Windows is not supported.
One language per repo. A polyglot monorepo is indexed as whichever language has the most git-tracked files. Override it with --language; multi-language merge is out of scope.
It never edits your code. Navigation and search only. If you want an agent that performs semantic renames and refactors, you want Serena, which is complementary rather than competing.
Indexing is an explicit step. Nothing is analysed live. Run jarvis index or jarvis watch to publish an index before querying it.
Semantic search is excluded. The Homebrew package deliberately omits the embedding stack. The semanticSearch tool remains registered and reports that distribution-specific limitation rather than pretending to return ranked vectors.
Language indexers are optional. The package embeds scip and both Zoekt binaries but does not install setup.sh. From a jarvis source checkout, add only the indexer matching your repo with its setup.sh --only ... selector and the toolchain that indexer requires.

Install

Four steps. The first two are once per machine, the third is once per repo, and the fourth is once per client.

Install jarvis

once per machine 
$ brew install jarvis-intelligence/jarvis/jarvis

Linux users install Homebrew/Linuxbrew first. The standalone package supports macOS and Linux on arm64/x86_64, installs jarvis and jarvis-server together, and embeds Python 3.12, dashboard assets, tree-sitter, watch, scip, and both Zoekt binaries. Homebrew supplies universal-ctags; no Python, uv, pip, or package index is needed.

Add a language indexer

optional, once per machine 
$ cd /path/to/jarvis-source
$ sh setup.sh --only scip-python

The Homebrew package does not install this script. Selectors are scip-typescript, scip-python, scip-java, and scip-swift. The first two need Node/npm; Java needs a JDK (Kotlin 2.2.0 exactly); Swift needs Xcode on macOS arm64. Use bash-shim for Maven Java repos on macOS after installing a modern Bash.

Index a repo

once per repo 
$ jarvis index /path/to/your/repo

The slug defaults to the directory name. Use jarvis list to see what is indexed and jarvis reindex <slug> to refresh it.

Register the server

once per client

In Claude Code, installing the plugin registers the MCP server for you: 

/plugin marketplace add jarvis-intelligence/jarvis-index
/plugin install jarvis@jarvis

Any other MCP client, or Claude Code without the plugin:

$ claude mcp add jarvis --scope user -- jarvis-server

That is it. Ask your agent to find every reference to AuthService and it will call findReferences instead of grepping.
